# 출퇴근 결정 안내

버스·지하철·혼합·도보 여러 경로를 혼잡도 가정과 비교하려면 `recipe`의 `compare_travel_options` 절차를 사용한다. 사용자에게 확인한 출발지·목적지(이동 중이면 현재 위치)를 기준으로 호스트 지도 도구에서 여러 후보를 받아 `data_source=user_provided_map`으로 전달한다. 지도 도구가 없으면 사용자 제공 후보를 사용하며 새 지도 API 키를 요구하지 않는다. 확인된 프로필/미리보기 속도는 `walking_speed_kmh`로 전달한다. 실제 후보가 없는데 합성 경로를 실제 추천처럼 제시하지 않는다. 이 순수 비교는 루틴 등록 없이 가능하며 아래 루틴 조회 절차를 요구하지 않는다.

임의 혼잡도 테스트 요청에는 별도 `simulate_congestion`을 사용한다. 사용자나 확인된 경로가 제공한 기본 이동시간·역내 도보·정차 수를 입력하고, 0~400%의 가정 값을 비교한다. 보행 대안, 목표 도착, 열차까지 남은 시간은 확인된 값만 전달한다. `source=simulation`, 검증되지 않은 가정 정책, 계산된 도보·정차 여유시간을 명시한다. 확률·실시간 지연으로 말하거나 실제 루틴과 경로를 자동 변경하지 않는다. 열차를 놓쳐 도착값이 `null`이면 다음 열차 정보가 필요하다고 안내한다.

혼잡도를 요청받으면 `get_subway_congestion`에 확인된 역명, 호선(1~8), 한국 시간, 요일 유형(`weekday`/`saturday`/`sunday`), 방향(`up`/`down`)을 전달한다. 도착정보의 `line_id=1001`과 이 도구의 `line=1`을 구분한다. 결과는 `dataset_as_of` 기준 30분 평균 통계이며 실시간 혼잡도라고 표현하지 않는다. 결측은 정보 없음으로 안내하고 통계만으로 경로 변경이나 탑승 실패를 판단하지 않는다.

WayNudge MCP의 `list_routines`를 먼저 호출해 현재 사용자의 루틴을 확인한다. 루틴이 없으면 등록에 필요한 출발지·도착지·좌표·도착 시각을 묻고 `manage-routine`으로 연결한다. 여러 루틴이면 사용자 요청으로 식별하고, 모호하면 선택을 묻는다. 사용자 ID나 토큰을 도구 인수에 넣지 않는다.

서울 시간 기준 요청 날짜를 `YYYY-MM-DD`로 확정하고 `get_commute_brief`에 `routine_id`, `date`, `current_route_id`를 전달한다. 현재 경로 ID는 사용자가 알려주었거나 도구에서 확인된 값만 사용하고, 없으면 `null`로 둔다. 명시적인 대안 비교 요청에는 같은 인수로 `compare_routes`를 사용한다. 이미 받은 비교 결과로 충분하면 재호출하지 않는다.

서버가 반환한 `prepare_at`, `leave_at`, `estimated_arrival_if_leaving_now`, `late_if_leaving_now`, `comparison.selected`, `should_switch`, `reason`을 짧은 한국어로 설명한다. 시간·도보 보정·전환 이득·순위는 직접 계산하지 않는다. 필요하면 후보의 소요 시간·환승·도보·요금을 그대로 비교한다. 현재 경로 유지 판단을 임의로 뒤집거나 도착을 보장하지 않는다.

- `active=false`: 해당 날짜가 요일·휴가·재택 등의 루틴 제외일임을 알린다. 공휴일 제외는 예약 알림 프롬프트에서 에이전트가 처리하며 서버에 공휴일 달력은 없다.
- `source=mock`: “모의 경로예요. 실제 운행 정보가 아닙니다.”를 포함한다.
- 실시간 미지원·오래된 정보 경고는 생략하지 않는다. “실시간 운행 상황은 확인되지 않아 예상치로 안내해요.”처럼 설명한다.
- 후보가 비면 “설정한 조건에 맞는 경로를 찾지 못했어요.”라고 설명하고 변경 가능한 조건을 묻는다. 제한을 자동으로 완화하지 않는다.
- API 실패·호출 한도 초과는 “교통 정보를 가져오지 못해 출발 시각을 확인할 수 없어요.”라고 알리고, 결과를 지어내거나 무한 재시도하지 않는다.

저장된 `walking_speed_kmh`는 거리가 있는 도보·환승 구간에 서버가 적용하며 버스·열차 시간은 바꾸지 않는다. 거리 없는 구간은 기존 배율로 계산된다. “A에서 B까지 N분 걸었어”로 보정을 요청하면 `manage-routine`의 보행 속도 보정 절차를 사용한다. 사용자 측정 또는 호스트 지도 도보 경로의 실제 거리가 필요하며 직선거리·시간만으로 속도를 만들지 않는다. 미리보기(`confirmed=false`) 후 명시적인 동의와 인증을 거쳐 본인 루틴에 저장한다.

루틴·제외일·피드백 변경이 필요하면 저장할 내용을 먼저 요약하여 사용자의 명시적 확인을 받은 뒤에만 해당 변경 도구에 `confirmed=true`를 보낸다. 조회 요청만으로 저장에 동의한 것으로 처리하지 않는다. 알림은 폴링 수신함이며 기기에 자동 푸시된다고 말하지 않는다.

`boarding`이 있으면 `station_name`, `planned_board_at`으로 어느 역에서 몇 시에 지하철을 타야 하는지 함께 안내한다. `next_observed_train_at`은 관측 도착예정으로 구분하고 탑승이나 목적지 도착을 보장하지 않는다. 반복 알림을 요청하면 `schedule-commute`를 사용하여 호스트 에이전트의 예약 기능에 등록한다. 공개 MCP의 교통 조회에는 인증이 필요 없지만 개인 루틴 저장·조회에는 사용자 Bearer 인증을 사용한다.
