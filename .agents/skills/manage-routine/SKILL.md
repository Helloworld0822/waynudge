# 루틴 관리

루틴 조회·변경은 `list_routines`를 먼저 호출한다. 기존 ID와 설정을 확인하고 사용자 요청에 해당하는 루틴을 선택한다. 입력에 사용자 ID·인증 토큰을 넣지 않는다. 루틴이 없으면 신규 등록을 진행하고, 여러 개라면 대상이 명확해질 때까지 저장하지 않는다. 보행 미리보기만 요청한 경우 개인 루틴 조회나 등록은 필요 없다.

등록·수정은 `upsert_routine`의 `routine` 전체 객체를 사용한다. 기존 루틴 수정 시 요청하지 않은 값을 유지한다. 필수 필드는 `id`, `name`, `origin`과 `destination`(각각 `name`, `lat`, `lon`), `arrival_time`(`HH:MM`, Asia/Seoul), `weekdays`(월=1~일=7), `preferred_modes`(`subway`, `bus`, `mixed`, `walk`), `max_transfers`, `max_walk_minutes`, `buffer_minutes`, `preparation_minutes`, `min_alert_interval_minutes`, `walking_factor`, `usual_route_id`다. ID를 임의 변경해 새 루틴을 만들지 않는다. 장소와 좌표는 사용자가 제공한 값을 사용하고 누락된 필수 조건을 묻는다.

기본값 제안이 필요하면 환승 2회, 도보 20분, 여유 10분, 준비 30분, 알림 간격 15분, 도보 배율 1.0, 평소 경로 ID `null`을 제안할 수 있다. 제안은 저장된 값처럼 말하지 않는다. 선호 이동수단은 엄격한 필터이며 `mixed`는 별도 값이다. 요일·좌표·도착 시각·선호 수단을 만들어내지 않는다.

휴가·재택 등 특정일 제외에는 `set_routine_day_status`로 `routine_id`, `date`, `enabled=false`를 보낸다. 특정일 출근에는 `enabled=true`를 사용한다. 날짜 설정은 요일보다 우선한다. 공휴일 제외는 호스트 예약 프롬프트에서 처리하며 서버에 공휴일 달력 API를 추가하지 않는다. 요청한 날짜만 변경하며 삭제·날짜 예외 초기화 도구가 있다고 가정하지 않는다.

실제 이동 기록은 `record_trip_feedback`으로 `routine_id`, `route_id`, `actual_minutes`, `walking_factor`를 보낸다. 실제 소요 시간은 사용자가 제공해야 한다. 도보 배율을 모르면 `null`로 보내고 추정 계산하지 않는다. 배율을 지정하면 루틴의 도보 배율도 바뀐다는 점을 요약에 포함한다. `actual_minutes`는 1~1440분, 배율은 0.5~3.0이다. 경로 ID는 이전 도구 응답이나 사용자 제공 값으로 확인한다.

모든 변경 전 대상·변경값·적용 날짜·피드백의 배율 영향까지 짧게 요약하고 사용자의 명시적인 확인을 받는다. 확인 전 `confirmed=true`를 보내지 않는다. 확인된 값이 달라지면 다시 확인한다. 성공 응답의 `saved=true`를 확인한 뒤 완료를 알린다. 실패하거나 응답이 불명확하면 저장됐다고 말하지 않는다. 피드백 저장은 중복 가능하므로 응답 누락 시 자동 재전송하지 않는다.

## 보행 속도 보정

“A에서 B까지 N분 걸었어”에는 실제 걸은 거리와 시간이 모두 필요하다. 사용자가 측정한 거리(`distance_source=user_measured`)를 받거나, 호스트에 지도 도보 경로 도구가 있으면 실제 걸은 경로와 일치하는 거리(`map_walking_route`)를 확인한다. 좌표의 직선거리나 대중교통 경로 전체 거리로 대체하지 않고, 시간만으로 km/h를 추정하지 않는다. 거리를 확인할 수 없으면 보정을 저장하지 않고 기존 추정치를 유지한다.

`record_walking_observation`에 `routine_id`, 관측마다 고유한 `observation_id`, `origin`, `destination`(이름·좌표), `distance_meters`, `elapsed_minutes`, `distance_source`, `confirmed=false`를 보내 미리 본다. 공개 미리보기에는 개인 프로필이 포함되지 않는다. 루틴이 없는 미리보기에는 저장된 ID라고 주장하지 않는 임시 ID를 사용할 수 있다.

측정값·거리 출처·계산된 속도·적용할 본인 루틴을 요약하고 명시적인 저장 동의를 받은 뒤, 사용자 Bearer 인증으로 같은 입력과 `confirmed=true`를 보낸다. 저장 전 본인 루틴을 조회해 확인한다. 재시도는 같은 `observation_id`를 유지하며 새 관측에만 새 ID를 쓴다. `saved=true`를 확인해야 저장 완료다. 기존 `walking_speed_kmh`는 일반 루틴 수정 시 보존한다.

저장 속도는 거리 정보가 있는 도보·환승 시간에 적용되며 버스·열차 운행시간은 바꾸지 않는다. 거리 없는 구간은 기존 도보 배율을 사용한다. 방향·경사·계단·신호대기에 따라 달라지는 관측이므로 반대 방향에서도 같은 시간이 보장된다고 말하지 않는다.

출퇴근 시각·순위·최적 경로 계산은 서버 도구에 맡긴다. 경로 조회를 함께 했다면 모의 데이터, 실시간 미지원, 빈 결과, 날짜 제외, API 실패를 숨기지 말고 한국어로 간결히 전달한다. 상시 위치 추적이나 푸시 알림을 약속하지 않는다.
