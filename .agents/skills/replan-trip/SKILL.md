혼잡도 조회가 필요하면 확인된 역·호선(1~8)·요일 유형·한국 시각으로 `get_subway_congestion`을 호출한다. `dataset_as_of` 기준 30분 평균 통계로 안내하고 실시간 열차나 칸별 혼잡도로 설명하지 않는다. 결측은 정보 없음이며 통계만으로 현재 열차의 탑승 가능 여부를 판단하지 않는다.

# 이동 중 재탐색

현재 위치에서 버스·지하철·혼합·도보 대안 여러 개를 비교하려면 `compare_travel_options`를 사용할 수 있다. 사용자가 확인한 현재 위치와 목적지의 이름·좌표를 받고, 호스트 지도 도구로 **현재 위치부터 남은 구간**의 여러 경로를 조회하거나 사용자 제공 후보를 받는다. GPS·이전 출발지·대화 배경으로 현재 위치를 추정하지 않는다. 지도 도구가 없으면 새 지도 API 키를 요구하지 않으며, 후보가 없는 실제 요청에 합성 경로를 대신 넣지 않는다.

`recipe`의 여러 경로 비교 절차에 따라 `origin`, `destination`, `data_source=user_provided_map`, 후보별 수단·전체/도보 시간·확인된 거리와 환승·요금, 사용자 혼잡도 가정을 전달한다. 확인된 보행 프로필/미리보기의 속도는 `walking_speed_kmh`에 넣는다. `current_option_id`는 입력 후보에 존재하는 현재 경로 ID만 쓴다. 놓쳐서 이용할 수 없는 경로는 후보에서 제외하며 다음 차 대기시간을 만들지 않는다. 결과는 실제 지연이 아닌 가정 비교로 안내하고 `selected_option_id`, `should_switch`, `reason`, 경고를 따른다. 이 비교에는 루틴 등록이 필요 없고 현재 위치나 경로를 저장하지 않는다. “그냥 테스트”일 때만 명시적인 합성 네 경로를 사용할 수 있다.

테스트용 혼잡도를 직접 지정한 요청은 `simulate_congestion`으로 별도 계산한다. `source=simulation` 결과의 도보·정차 여유시간과 탑승/도착 조건을 가정으로 설명하고 실제 지연·지연 확률로 표현하지 않는다. 이 결과만으로 `replan_trip`의 현재 경로를 변경하거나 놓친 열차 이후의 도착 시각을 만들어내지 않는다.

저장된 루틴을 `replan_trip`으로 재탐색할 때는 먼저 `list_routines`를 호출해 루틴 ID와 목적지를 확인한다. 등록된 루틴이 없으면 등록부터 안내한다. 사용자가 직접 제공한 현재 역·위치와 좌표, 서울 기준 날짜, 이동 상태를 확인한다. 현재 위치를 GPS·대화 배경·이전 목적지에서 추정하거나 상시 추적하지 않는다. 좌표가 없으면 요청하며 임의 좌표로 도구를 호출하지 않는다.

`replan_trip`에 다음 인수를 보낸다.

- `routine_id`, `date`: 확인한 루틴 ID와 `YYYY-MM-DD` 날짜.
- `current_location`: 사용자가 제공한 `name`, `lat`, `lon`.
- `stage`: 역에 있으면 `at_station`, 도보 이동 중이면 `walking`, 환승을 놓쳤으면 `transfer_missed`.
- `current_route_id`: 사용자가 알려주거나 기존 도구 응답에서 확인한 경로 ID. 없으면 `null`.
- `blocked_route_ids`: 사용할 수 없는 것으로 확인한 경로 ID 배열. 환승 실패에는 하나 이상 필요하다. ID를 모르면 `get_commute_brief` 또는 `compare_routes` 결과를 보여주고 어느 경로인지 사용자에게 확인한다. 노선 이름을 경로 ID로 만들어 넣지 않는다.

서버가 반환한 선택 경로, `should_switch`, `reason`, 예상 도착과 지각 여부를 한국어로 간결하게 설명한다. 재탐색은 현재 위치를 임시 출발점으로 삼고 준비 시간을 0으로 적용한다. 저장된 출발지나 루틴을 바꾸지는 않는다. 시간, 전환 비용, 도보 속도, 경로 순위를 자체 계산하지 않는다. 역 출구나 승강장 단위 동선을 만들어내지 않는다.

`source=mock`이면 모의 결과임을 표시한다. 실시간 미연동·오래된 정보 경고를 포함하고 실제 운행이나 도착을 보장하지 않는다. `active=false`이면 해당 날짜의 루틴이 제외되었다고 설명한다. 후보가 없으면 조건과 제외 경로 때문에 선택할 수 없다고 알리고, 제외한 경로를 자동 복원하지 않는다. API 실패에는 현재 경로의 운행 여부도 확인할 수 없다고 알리고 재시도를 반복하지 않는다.

변경 도구를 사용할 경우 저장할 루틴·날짜 예외·피드백 내용을 요약하고 명시적인 사용자 확인 이후에만 `confirmed=true`를 보낸다. 현재 위치 제공이나 재탐색 요청을 저장 동의로 간주하지 않는다.
