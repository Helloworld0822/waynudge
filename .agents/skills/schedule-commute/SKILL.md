# 출퇴근 예약 알림

`list_routines`로 대상 루틴을 확인한다. 알림을 받을 시각(HH:MM), 반복 요일, 시간대를 확인한다. 시간대 기본값은 Asia/Seoul이며 사용자에게 명시한다. "매일"은 월~일, "평일"은 월~금이다. 시각이 없거나 여러 루틴 중 대상이 불분명할 때만 누락된 값을 묻는다. 이미 명확하게 요청한 예약을 다시 승인받지 않는다.

`prepare_commute_reminder`에 `routine_id`, `notification_time`, `weekdays`(월=1~일=7)를 전달한다. 서버의 일정·프롬프트를 사용하고 반복 시각을 자체 계산하지 않는다. 반환된 `created=false`는 일정이 아직 생성되지 않았다는 뜻이다.

호스트 에이전트의 실제 예약/자동화 도구를 찾아 `title`, `schedule_ical`, `prompt`, `timezone`을 전달하여 등록한다. 같은 루틴의 기존 예약이 있으면 해당 예약을 수정해 중복을 막는다. 텔레그램·메신저 API를 사용하지 않는다. 호스트 예약 도구가 없으면 "이 환경에는 예약 알림 도구가 없어 등록하지 못했습니다"라고 말하고 일정 초안만 제공한다. 계획 생성이나 대화 응답만으로 예약 완료라고 말하지 않는다.

예약 프롬프트에는 "대한민국 공휴일·대체공휴일 제외"를 유지한다. 공휴일은 예약 에이전트가 확인하며 Rust 서버에 공휴일 달력이나 별도 공휴일 API를 요구하지 않는다. 매 실행마다 서울 기준 오늘 날짜로 `get_commute_brief`를 호출한다. `active=false`인 휴가·재택·요일 제외일은 알림을 생략한다.

알림에는 준비 시각, 출발 시각, `boarding.station_name`과 `boarding.planned_board_at`을 포함한다. 실제 도착 관측과 계획상 승차 시각을 구분한다. 실시간 조회가 필요하면 역·호선·방향이 확인된 값으로 `get_subway_arrivals`, 제공자별 정류소 ID가 확인되면 `get_bus_arrivals`를 사용한다. 혼잡도는 제공된 값만 사용하고 빈 데이터는 여유롭다고 해석하지 않는다. Mock·오래된 관측·API 실패를 명시한다.

실제 예약 도구가 성공하고 식별자와 일정이 확인된 뒤에만 "매주 월~금 오전 7:30(한국 시간), 공휴일 제외로 등록했습니다"처럼 완료를 알린다. 예약 ID와 변경·해제 방법도 함께 제공한다.
