## 연결 및 저장

Vooy의 기존 사용자 지정 MCP 연결은 과거의 10개 도구만 저장하고 있었습니다. 설정 화면에는 도구 목록 새로고침이 없고 같은 주소의 중복 등록도 거부되어, 같은 공개 MCP 주소를 다시 연결했습니다. Vooy의 실제 연결 완료 화면에서 `12 validated tools from waynudge.helloworld0822.xyz`를 확인했습니다.

재연결로 바뀐 서비스 참조를 레시피의 서비스 연결 제안 화면에서 검토하고 적용했습니다. 필요한 서비스는 현재 연결된 `rmcp`와 카카오맵만 남겼으며, 예전 연결을 요구하던 경고가 사라졌습니다. 이 작업의 제안에는 서비스 연결 변경 1개만 있었고 본문·이름·예시는 변경하지 않았습니다.

본문 저장 후 새로고침하여 테스트 모드가 남아 있는지 확인했습니다. 마지막에는 세 가지 상황과 기대 행동이 각각 저장한 값과 일치하고 공개 범위 스위치가 `false`인지 확인했습니다.

초기 음수 입력 테스트에서는 도구의 입력 오류 이후 Vooy가 서비스 장애와 팀 통보를 주장했습니다. 스킬에 호출 전 범위 검사, 입력 오류와 연결 장애 구분, 실행하지 않은 통보를 주장하지 않는 규칙을 추가했습니다. 실제 Vooy 본문에도 같은 변경을 저장하고 새 테스트 세션에서 재검증하여 위 결과를 확인했습니다.

별도로 공개 MCP에 음수 혼잡도를 직접 전달하여 서버가 오류를 반환하는 것도 확인했습니다. 스킬의 YAML 및 기본 구조는 `quick_validate.py`로 검증했습니다. 이번 작업은 Rust 코드를 수정하지 않았으며 기존 서버의 45개 테스트 결과는 이전 검증 기록에 있습니다.

시뮬레이션의 추가시간 계수는 검증되지 않은 테스트 가정입니다. 실제 지연 예측이나 지연 확률의 검증 결과를 뜻하지 않습니다.
